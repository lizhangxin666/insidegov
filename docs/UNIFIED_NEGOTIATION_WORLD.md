# 统一政企协商世界

核心招商世界现已吸收政企协商实验室的信息与回应协议，形成一套嵌套协商：

```text
企业表面需求
→ 招商局澄清真实需求
→ 城市维护 GovBelief
→ 招商局形成候选政策包
→ 财政局规则审核
→ 市领导重组工具并生成分期
→ 企业接受 / 还价 / 退出
→ 下一季度吸收还价重新会商
→ Q3 在已接受城市中最终选址
→ 条件合同、建设、履约和产业演化
```

## 数据边界

- `LatentNeed`：企业与世界引擎知道，政府不可直接读取；
- `StatedNeed`：企业第一轮公开表达；
- `GovBelief`：每座城市独立维护对企业需求的理解；
- `ExternalNegotiationRound`：记录澄清、理解更新、内部会议引用和企业回应；
- `NegotiationRound`：继续记录招商局、财政局、市领导的内部会商；
- `Promise`：只有最终选址后的政策包才转换为条件承诺。

## 可执行回应

企业回应不是展示文本：

- `counter`：现金/股权下限与分期要求进入下一季度招商观察；
- 招商提案可吸收企业要求，但仍会被财政硬上限压回；
- `terminate`：该城市被移出 Q3 最终选址候选；
- `accept`：只表示进入最终跨城市比较，不等于提前签约。

## Q1—Q3

每座城市每季度产生：

1. 一条政府内部 `NegotiationRound`；
2. 一条政企外部 `ExternalNegotiationRound`；
3. 招商、财政、领导和企业回应四条行动审计记录。

三座城市、三个季度最多形成 9 条内部会商和 9 条外部协商记录。

## 与独立协商实验室的关系

独立协商实验室仍用于比较七种协议的机制效应；统一核心世界只吸收其基础能力，
不复用其财政结算，避免两个规则引擎同时修改同一城市预算。

当前统一世界默认采用 `clarify_first`。后续可在不修改财政与生命周期规则的前提下，
把七种协议作为核心世界的可切换机制矩阵。

## 验收

- 企业 Q1 还价会提高 Q2 招商提案中的对应工具诉求；
- 财政规则仍保证最终政策包不突破现金、股权和总成本上限；
- Q3 退出城市不会被企业董事会选中；
- 最终合同仍由规则引擎生成分期承诺；
- 世界序列化、历史分支、Agent 采访和自动报告继续兼容。
