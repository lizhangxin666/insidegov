# 人才对接场景研究说明：需求 ↔ 政策 ↔ 能力映射

> 场景定位：**沟通协商机制**是政企互动的核心。本场景把「政府对政策做不做解释、
> 何时解释、以何种形式解释（官话 vs 人话）」以及「不同主体的解读反应」建成一个
> 可运行的协商实验，并用 2x2 反事实回答：**表达方式与翻译中介，分别贡献了什么？**

## 1. 场景叙事：为什么是人才对接

青禾市是一座小企业集中的城市。三家小企业（清源材料、睿控装备、蓝芯生物）有真实的
技术瓶颈，需要高校人才；两所大学（青禾理工大学、云麓大学）供给六名人才，分属三种
类型：

| 人才类型 | 代表 | 能力画像 | 核心顾虑（私有信息） |
|---|---|---|---|
| 青年教师 | 周然、林蔚、苏宸 | 技术强、执行力高、投入度高 | **身份**（评职称/编制）、**学术**（考核/晋升/论文） |
| 资深教授 | 陈鹤鸣、顾明远 | 学术权威、技术顶尖 | **投入度低**（指挥团队不亲自做）、学术声誉沉没成本 |
| 产业专家 | 沈砚 | 工程化与产业落地强 | **报酬**与市场化机会 |

这正是「人才对接」案例的抽象：**小企业需要青年教师——有能力但不敢脱离学术圈
（考核、晋升、声誉沉没成本）；功成名就的教授又不亲自做，或学术需求 ≠ 产业需求**。
「落地和对接过程中产生很大问题」的根源不是人才不够，而是**需求、政策、能力三者
之间的映射失败**。

## 2. 三大支柱在本场景的落点

| 设计支柱 | 本场景机制 | 关键问题 |
|---|---|---|
| 产业网络系统 | 企业技术需求 → 人才能力向量的结构匹配（cosine），签约后知识外溢到产业网络 | 谁有资格对接？能力不匹配直接出局 |
| 信任与信息系统 | 表达层与解读层分离：同一政策文本，不同主体解读不同；官话 vs 人话 = 「传导率」 | 谈得懂不懂？理解度/信任/覆盖度量化 |
| 沟通协商机制（核心） | 需求表达 → 政策设计 → 多轮解读协商 → 中介翻译撮合 | 谈不谈得拢？多轮讨价还价与签约 |

**匹配成功率的定义**：企业把模糊诉求翻译成结构化需求向量（`compose_demand`），
政府针对候选人的公开画像设计政策工具包与语言模式（`design_policy`），候选人按
「理解度 × 信任 × 覆盖度」的加权感知决定接受、讨价还价或拒绝（`interpret_offer`）。
需求必须对应到政策，政策必须对应到人才能力——三者对齐才签约，这就是「精准表达」
的量化定义。

## 3. 四重错位：对接失败的根源

1. **身份错位**：企业要的是「做事的人」，教师担心的是「脱离体制的身份成本」。
2. **语言错位**：企业讲产线、良率、交付；学者讲课题、论文、考核——同一句话传导率不同。
3. **激励错位**：教授指挥团队而非亲自投入，学术诉求 ≠ 产业诉求，转化慢。
4. **转化成本**：信息不透明，双方无法验证对方承诺是否可信。

对应政策工具：

| 顾虑 | 政策工具 | 边际成本 |
|---|---|---|
| 身份（职称通道） | `title_track` | 1.0 |
| 学术（课题折算/考核） | `lab_credit`（联合实验室） | 0.6 |
| 报酬（安家补贴） | `relocation` | 1.0 |
| 风险（揭榜/开放课题） | `open_call` | 0.35 |
| 转化成本（平台翻译） | `interpreter` | 0.1 |

## 4. 量化指标：理解度 / 信任 / 覆盖度

一次 offer 到达人才端时，被拆成三个可计算的量：

- **理解度 understanding** = 0.42 基础 + 语言模式加成（人话 +0.20，官话 +0.02）
  + 是否提供解释 +0.07 + 人才解读技能 × 0.15 + 平台翻译 × 0.13。
- **信任 trust** = 人才对政府的基础信任 + 城市客观信用利差 × 0.30 + 平台信息覆盖 × 0.10。
- **覆盖度 coverage** = 顾虑加权工具覆盖 × 0.75 + 薪资满足比 × 0.25。

人才端感知 = 理解 × 0.35 + 信任 × 0.30 + 覆盖 × 0.35，与个人「接受门槛」
（风险厌恶 + 机会成本）比较，决定 accept / counter / reject。

## 5. 2x2 反事实实验

同一初始世界（同种子、同人才、同企业、同财政），仅切换两个世界级开关：

| | 无平台（直连） | 有平台（翻译撮合） |
|---|---|---|
| **官话** | 官话直连（基线） | 官话 + 平台 |
| **人话** | 人话直连 | 人话 + 平台 |

运行：`uv run insidegov talent-compare --seed 42 --quarters 16`

## 6. 参考结果（确定性认知层，seed=42，16 季度）

| 变体 | 对接成功率 | 平均理解度 | 签约数 | 企业平均技术存量 |
|---|---:|---:|---:|---:|
| 官话直连 | 0.000 | 0.616 | 0 | 30.1 |
| 人话直连 | 0.333 | 0.946 | 4 | 67.2 |
| 官话 + 平台 | 0.200 | 0.772 | 3 | 58.0 |
| 人话 + 平台 | 0.333 | 1.000 | 4 | 67.2 |

**结论速读**：

1. **语言是主传导机制**：官话直连全军覆没（0 签约），人话直连 4 签约——
   政策内容没变，只是「说人话 + 解释」，对接成功率从 0 到 1/3。
2. **平台是官话的救火队**：官话 + 平台把 0 签约救回 3 签约；但人话下平台
   边际收益趋零——翻译器在语言不通时价值最大，是替代品而非互补品。
3. **加钱不解决表达问题**：覆盖度再高（工具给足），理解度不足依然拒签；
   相反，理解到位后同样的预算能签更多人，财政支出反而更低（人话直连支出
   592.99 < 官话直连 600.00，且产出 4 个落地项目）。
4. **信任在无冲击时稳定**：16 季度无违约时信任持平 0.62；施加 `fiscal_shock`
   或 `credibility_shock` 干预会击穿信任，直接压低签约——见
   `tests/test_talent_engine.py::test_fiscal_constraints_never_go_negative`。

## 7. 运行入口

```bash
# 单场景
uv run insidegov talent --language plain --platform --quarters 16
# 2x2 反事实
uv run insidegov talent-compare --seed 42 --quarters 16
# 多种子矩阵 + 报告（.insidegov/reports/talent-matrix-*.md）
uv run insidegov talent-matrix --seeds 11,23,42,57,89 --quarters 16
```

API：`POST /talent-worlds`（创建人才世界）、`GET /experiments/talent-comparison`
（2x2 反事实）、`POST /experiments/talent-matrix`（多种子矩阵）。

## 8. 与赛题的联系

- 官方评分维度之一是「**沟通协商机制**」：本场景把它做成显式的四步协商环
  （需求表达 → 政策设计 → 解读协商 → 翻译撮合），每一步可替换 LLM 认知策略。
- 「**预设不同企业的解读反应导致不同结果**」：人才是异质的（青年教师/教授/专家），
  同一政策包在三人身上的理解度、信任、覆盖度不同，签约结果不同——解读差异
  是内生变量而非外生噪声。
- 「**需求要对应到政策，政策要对应到企业技能**」：`compose_demand` 产出结构化
  需求向量，`design_policy` 必须把政策工具对到候选人的顾虑，`capability_match`
  低于 0.25 直接出局——三者映射失败即「对接失败」，这是匹配成功率的来源。
