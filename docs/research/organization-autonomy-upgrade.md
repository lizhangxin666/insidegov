# 组织自主性升级：计划、开放行动、机会窗口与长期学习

本次升级把组织 Agent 从“一轮一决策”改为跨季度的受约束行动者。四个模块共用同一条证据链：

```text
比较策略路径并保存计划树
→ 感知政策、竞争、财政与注意力窗口
→ 执行计划动作或提出目录外行动
→ 权限、资源、合法性与效果幅度审查
→ 更新程序、关系与客观世界
→ 记录计划偏离并形成组织经验
→ 下一轮规划读取信任、惯例、否决历史和可迁移教训
```

## 1. 可检验的多步计划

每个城市的招商局、财政局、园区和市领导分别保存 `OrganizationPlan`。计划不是隐藏的思维链，而是可审计的决策产物，包括：

- 两到三条候选策略及其收益、风险和评分；
- 被选择的策略；
- 两到五个跨季度节点；
- 每个节点的最早和最晚执行季度；
- 前置条件、成功路径、失败后的重规划入口；
- 原计划动作、实际动作和偏离理由。

系统不保存模型内部推理过程，只保存足以被研究者复核的计划结构与行动理由。

## 2. 开放行动与安全执行

Agent 可以通过 `propose_open_action` 提出目录外行动，例如上级背书、行业协会联盟、示范工程、会议窗口、战略等待、跨部门工作组和专家论证。上述机制只是示例，不再是模型必须从中选择的固定枚举；Agent 可以提供新的 `mechanism`、`intent`、`domain`、`arena`、目标主体、信息请求、资源申请、时点和可逆性。

开放不等于任意。规则引擎依次检查：

1. 该机制是否属于本部门职责；
2. 是否试图代替其他部门或企业作决定；
3. 是否凭空申请财政、股权、土地、信贷等资源；
4. 请求改变的状态维度是否可执行；
5. 效果幅度是否超过实验上限。

检查结果不是简单的同意或拒绝，而是：

```text
execute / execute_with_limits
requires_coordination / requires_approval
blocked
```

资源请求会被编译为 `request_resource` 和 `request_approval`，而不是直接增加预算。
通过审查后，动作只会被映射为消息、信息请求、会议、提案、审批事项，或议程、联盟、程序完整度、注意力、审批速度与可信度的小幅变化。财政、合同和生产状态仍不能由 LLM 直接修改。

完整字段与边界见 [`agent-action-boundaries.md`](agent-action-boundaries.md)。

## 3. 内生政治机会窗口

`OpportunityWindow` 由世界状态和可复现随机流生成，当前包括：

- 上级产业政策信号；
- 重大会议日历；
- 竞争城市率先报价；
- 财政压力收窄政策空间；
- 舆情改变领导注意力；
- 部门负责人调整。

窗口具有开始、结束、强度、触发证据、可见主体和状态效果。Agent 可以提前规划，但不能提前知道尚未出现的窗口；窗口发生后才进入其局部观察。

## 4. 长期组织学习

每个组织保存独立的 `OrganizationLearningState`：

- 对其他部门的稳定信任；
- 对企业谈判类型的信念；
- 行动尝试、成功率和策略偏好；
- 重复成功后形成的组织惯例；
- 财政否决次数和协调成功次数；
- 当前领导代际与记忆继承比例；
- 本项目教训与可跨项目迁移的教训。

连续财政否决会提高分期、试点和新型组织行动的偏好。负责人调整时，个人关系与策略偏好部分衰减，但制度档案、组织惯例和部分历史记忆被保留，从而区分“个人记忆”与“组织记忆”。

## 研究边界

这些模块用于研究行动路径、程序冲突和组织适应，不证明模拟行为与现实政府完全一致。计划评分、窗口发生率、信任更新速度和效果上限仍需用真实案例校准，并通过多 seed、机制消融和失败案例报告检验。
